# 小白安装（CentOS 7）

主控只要一条命令，和 CDNFLY 的 `master.sh` 一样。不用填 IP，不用在服务器上编译。安装包已经放在仓库的 `pkg/master.tar.gz` 和 `pkg/redi-multi.tar.gz`。在 **主控** 上用 root 执行：

```bash
curl -fsSL https://github.com/freejbgo/301/raw/main/master.sh -o master.sh && chmod +x master.sh && bash master.sh
```

仓库需要是公开的，这台机器要能访问 GitHub。系统是 **CentOS 7.9**（7.x 也可以），SSH 用 **22** 端口。命令会自己识别公网 IP、下载安装包、装 Nginx / PHP / MariaDB。网卡上如果只有内网 IP，脚本会去查云平台记录的公网地址，再不行就看公网访问这台机器时看到的出口地址，不用自己填。最后一行是 `主控安装完成`。

装完后：

- 后台：`http://主控公网IP/admin`
- 用户名：`admin`
- 初始密码：`Redi301@Install2026`（登录后页面会要求马上改掉）
- 数据库密码：主控上的 `/root/301-passwords.txt`

云控制台安全组：两台机器都放行 TCP **22 / 80 / 443**。主控的 **3306** 只允许节点公网 IP 来访问。

程序目录和原来的脚本相同：主控 `/opt/301/master`，节点 `/opt/redi-multi/redi-multi`。脚本每一步做了什么见 [DEPLOY-centos7.md](../DEPLOY-centos7.md)。

下面从后台建节点开始。节点也是一条命令，主控装完后屏幕上会打出来。Token 只在后台显示一次，要贴进那条命令。

---

## 浏览器里新建节点（拿 Token）

在你自己的电脑上打开浏览器，地址栏输入：

`http://主控公网IP/admin`

例如主控 IP 是 `203.0.113.10`，就打开 `http://203.0.113.10/admin`。

1. 用户名填 `admin`，密码填 `Redi301@Install2026`，登录。
2. 页面要求改密码时，设一个新密码，记下来。新密码不要再用 `Redi301@Install2026`。
3. 左侧打开 **站点配置 → 节点管理**。
4. 点新建。名称随便写，例如 `node-1`。**主公网 IP** 填云控制台里这台节点的公网 IP。启用打开。保存。装节点时脚本还会打印它识别到的地址，和这里对一下。
5. 弹出的 **Token** 只显示这一次。立刻复制到记事本。关掉窗口就看不到了。丢了就在这一行上做「轮换」，用新 Token，旧的同时失效。

Token 是一长串字母和数字，中间没有空格。

---

## 安装节点（只在节点做）

主控装完后，屏幕上会打出一整条节点命令，里面已经带上主控 IP 和安装密钥。在 **节点** 上用 root 执行那一整条，只把最后的 `节点Token` 换成后台复制的 Token。形式是：

```bash
curl -fsSL https://github.com/freejbgo/301/raw/main/node.sh -o node.sh && chmod +x node.sh && bash node.sh --master-ip 主控IP --install-key 密钥 --token '节点Token'
```

不用填节点自己的 IP。网卡上如果只有内网地址，脚本会去查云平台和公网出口，和主控一样。它会连回主控，把这个外部地址加入数据库放行名单，然后装上节点程序。

后台「节点管理」里这条节点的 **主公网 IP** 填脚本打印的 `本节点公网 IP`。

成功标志：`节点安装完成`，并且 `redi-multi` 是 `active`。中途出现 `警告: REDI_MASTER_INSECURE=1` 是正常的，第一次用 IP 访问主控就会这样。

主控云安全组的 **3306** 要允许这个节点公网 IP。22、80、443 两台机器都要放行。如果提示数据库连不上，放行 3306 后把同一条命令再执行一次。

这条命令不要发到聊天软件里。里面的安装密钥可以让人到主控放行数据库。

---

## 装好之后（给客户域名用之前）

现在后台可以用 IP 打开，节点也已经连上主控。客户域名还要在后台做这些事（点哪里见 [CONSOLE.md](CONSOLE.md)）：

1. **站点配置 → DNS 与节点池**：填写平台主域名。
2. 按页面上的表，到你的 DNS 服务商给 `pool` 加 **A 记录**，值是节点公网 IP。有多台节点就加多条 A。
3. **站点配置 → 分组管理**：新建一个分组。
4. **站点配置 → 域名管理**：添加客户域名，把页面上的 **CNAME 目标** 发给客户。客户把域名 CNAME 到这个目标。
5. 预检显示已指向后，点 **申请证书**。

客户不要把域名 A 到某一台节点的 IP。说明可直接转给客户：[CUSTOMER-CNAME-HTTPS.md](CUSTOMER-CNAME-HTTPS.md)。

对外给客户用之前，主控要改成 **https 域名**（节点访问主控也改成 `https://`）。第一次安装为了能先打开后台，用的是 `http://IP`。改法见 [DEPLOY-centos7.md](../DEPLOY-centos7.md) 第 2 节末尾。上线前打勾用 [LAUNCH-CHECKLIST.md](LAUNCH-CHECKLIST.md)。

## 再加一台节点

1. 新机器也是 CentOS 7。安全组放行 22、80、443。主控安全组的 3306 再加上这台机器的公网 IP。
2. 后台 **节点管理** 再新建一条。主公网 IP 先填云控制台里看到的地址；装的时候脚本还会再打印一次它识别到的地址，对一下。
3. 在新机器上执行列表下方的 `node.sh` 命令，或直接复制这一行「查看 Token」弹窗里的整条命令。`--install-key` 保持不动，`--token` 后面才是这条节点的 Token。节点 IP 不用填，脚本会自己识别并让主控放行。
4. DNS 里 `pool` 的 A 记录加上这个新 IP。

同一台机器上的第二个公网 IP，填在后台这一条节点的「其他公网 IP」里，不要再装一遍程序。

## 出错了

| 屏幕上的字 | 处理 |
|------------|------|
| `节点Token` 或 `缺少 --token` | 把命令最后的占位文字换成后台复制的那一串，再执行一次。简体是 `节点Token`，繁体是 `節點Token`，英文是 `Node Token` |
| `这个脚本只用于 CentOS 7` | 系统不是 CentOS 7。重装成 CentOS 7.9 后再做 |
| `下载代码失败` 或 `仓库里没有安装包` | 先把仓库设为公开，主控要能访问 github.com，然后重新执行上面的一条命令 |
| `没能自动识别公网 IP` | 再执行一次：`MASTER_IP=主控公网IP bash master.sh` |
| `磁盘剩余不足` | 系统盘扩容到至少 20GB |
| `需要 PHP 8.0` | 把这一行上面的 yum 报错保留，在主控重新执行 master.sh |
| `连不上` 且提到 `redi_node` 或 `3306` | 云安全组：主控的 3306 来源要包含脚本打印的节点公网 IP。放行后在节点把同一条命令再执行一次 |
| `redi-multi 没有保持运行` | 节点上 80 或 443 已被别的网站程序占用。停掉占用的程序后，再执行一次同一条命令 |
| `缺少 --install-key` 或 `主控没有接受` | 用主控屏幕上打印的整条命令，不要自己删掉 `--install-key`。主控要允许 root 公钥登录 |
| `拿不到主控` 的 SSH 指纹 | 节点要能访问主控的 22 端口。云安全组放行后重试 |
| 后台打不开 | 云安全组和系统防火墙都要放行 80。地址是 `http://` 加主控公网 IP 加 `/admin` |
| 节点列表没有心跳 | Token 要整串贴在 `--token` 后面，再执行一次。主控地址是 `http://主控IP` |

主控命令中途失败时，修好之后再执行一次同一条命令即可，不必重装系统。

数据库 root 密码和程序用的数据库密码在主控 `/root/301-passwords.txt`。这个文件只留在服务器上，不要发到聊天软件里。
